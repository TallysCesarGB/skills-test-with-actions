## CATEGORIES TO ANALYZE
Identify and classify smells under the following categories. Include any other 
relevant smell not listed here if found.

### Structural / Method-Level
1. **Long Method/Function** – units doing too much or exceeding reasonable length/complexity
2. **Long Parameter List** – functions/methods with excessive parameters
3. **Duplicated Code** – identical or near-identical logic repeated across the codebase
4. **Dead Code** – unreachable, unused, or commented-out code left behind
5. **Speculative Generality** – unnecessary abstraction, unused hooks/parameters "for future use"
6. **Complex Conditionals / Deep Nesting** – nested if/else, loops, or boolean logic that hurt readability

### Class / Module-Level
7. **Large Class/Module / God Object** – classes, modules, or files with too many responsibilities (SRP violation)
8. **Data Class / Anemic Domain Model** – classes that only hold data with no behavior, while logic lives elsewhere
9. **Lazy Class** – classes/modules that do too little to justify their existence
10. **Data Clumps** – groups of data/parameters that always travel together but aren't encapsulated

### Coupling / Relationship Smells
11. **Feature Envy** – functions/methods more interested in another class/module's data than their own
12. **Inappropriate Intimacy / Shotgun Surgery** – tightly coupled classes/modules where one change ripples across many files
13. **Middle Man** – classes that delegate almost everything without adding value
14. **Message Chains** – long chains of calls navigating object graphs (a.b().c().d())
15. **Refused Bequest** – subclasses/implementations that inherit/implement members only to throw "not implemented" or no-op them (LSP violation)
16. **Inheritance Misuse** – using inheritance for code reuse where composition would be more appropriate

### Polymorphism / Type Smells
17. **Primitive Obsession** – overuse of primitives (strings, numbers, arrays/maps) where a dedicated type/value object would be more appropriate
18. **Switch/Type-Checking Statements** – repeated type checks or large switch/case blocks that could be polymorphism or Strategy pattern
19. **Type Casting / Unsafe Type Checks** – excessive runtime casting, `any`/`object` types, reflection misuse

### Architecture / Cross-Cutting
20. **Mixed Responsibilities / Layering Violations** – business logic mixed with I/O, presentation, persistence, or framework code
21. **Hidden Dependencies / Global State** – reliance on globals, singletons, static mutable state, hidden side effects
22. **Hard-Coded Configuration / Magic Numbers/Strings** – literals that should be constants, enums, or config values
23. **Poor Error Handling** – swallowed exceptions, broad catch-alls, missing validation, inconsistent error strategy
24. **Testability Issues** – tight coupling to external resources (DB, network, filesystem, time) preventing unit testing
